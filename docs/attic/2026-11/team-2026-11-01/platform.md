## 0. 摘要（结论先行）

她已把「读」几乎用满、「写」刻意留白：13 类读端点在线，写只开了图文动态/删除/编辑/点赞/收藏/私信/评论/弹幕八条窄门。
最大缺口按性价比排序：**置顶与评论区维护（低风险高生活感）→ 专栏/Opus 长文（助眠文案天然载体）→ 视频投稿（最高价值、最高风险，必须人工闸门）**。
412 是 IP/指纹级风控，不是预算超标（当日写仅 1 次），唯一正确姿势是退避+复核+像人一样接受失败。视频上线顺序：人工网页首发验证审核→**逆向投稿 API 路线已被 2026-01 bilibili-API-collect 律师函关停事件否决**，剩官方开放平台（V7）与「主人网页代投」双轨；AIGC 显式+隐式标识 2025-09 起是法定义务，「正文不出戏」需主人重划边界。30 天节奏参照小体量助眠 UP：图文 3-5/周、视频 2/月、公开互动每日 1-2 个集中窗口、每周留沉默日。

## 2. 412 风控专题

### 2.1 证据链（已验证事实）

1. **时间**：2026-10-31 11:49Z（本地 19:49），面板三次放行的图文发布全部失败；`CURRENT.md` 记「除 reporting bug 已修（`d481d89`），重试窗口约 20:55 本地后」。
2. **端点面**：`~/.bili-ai/traffic-state.json` 实测（本次普查读取）：`reason:"HTTP 412 / code unknown"`、`riskEndpoint:"/x/polymer/web-dynamic/v1/feed/space"`、`streak:1`。当日 `operations` 仅 `/x/dynamic/feed/draw/upload_bfs` 一条 `confirmed`，**create/dyn 无 confirmed 记录**——与 CURRENT「只完成了传图、发布未成功，无半发动态」互相印证。
3. **频率面**：当日该账号 `writeDay:1`（只有传图算了一次成功写）、`readDay:163`——远未触及 writeDaily 30/readDaily 3000 本地预算。**412 不是她打爆本地额度造成的**，与 2026-10-22 `bili-api.mjs` 头注的社区实测一致：「412 是 IP 级限流，换接口救不了」。
4. **覆盖面**：写端点 `x/dynamic/feed/create/dyn` 回 412 风控页 HTML；同域读端点 `polymer feed/space` 实测同样回 HTML；老读端点 `dynamic_svr/space_history` 被打码（非 JSON）。即**整个动态业务域（写+新旧读）被同一策略罩住**，单接口绕行无效。
5. **双账号并存**：traffic-state 里有两个账号的额度记录——同一进程组对同一 IP 的叠加流量会更快触发风控（假设 H1，验证法：单账号日写 ≤5、观察 412 是否消失）。

### 2.2 会加重风控的做法（按代码现状点名）

- **412 后连续重试 create/dyn**：每次发布天然是 2 连 POST（upload_bfs+create/dyn），失败即重试=对风控页扇耳光。现有 `traffic.mjs` 熔断（streak 指数退避 5→30min 封顶，`bili-api.mjs` L167-176）方向正确；**面板「✗失败再点✓」的人工重试同样计入重试风暴**，要在放行入口提示「今天不再试」。
- **换端点/换 UA 硬闯**：space_history 打码后改 feed/space 是对的（换数据源为读服务）；但把**写**操作在多端点间跳（老 dynamic_svr/create vs 新 create/dyn）会被视为指纹漂移，更糟。
- **UA/请求头与 cookie 指纹不一致**：现各命令 UA 字符串不统一（Mozilla/5.0 全串 vs 裸 `Mozilla/5.0`，见 comment/dm/feed），buvid3 只在部分命令带上。真人浏览器是全套指纹一致的；不一致本身是机器人特征（假设 H2，验证法：统一一次流量画像后连发一周观察 412 频次，只读 `whoami`/`nav` 即可核对指纹返回）。
- **机器化时间分布**：发布动作全部落在「面板放行瞬间」，整分整秒间隔（minGapMs 1500 太整齐）。真人发帖前后有浏览轨迹。
- **写预算误当风控预算**：writeDaily 30 对 B 站动态域太宽——真人 UP 一天发不了 30 条。本地额度该对齐「人味」而非对齐「封号线」。

### 2.3 可执行的规避与退避策略（建议，不改动现码）

1. **发布前置「路况探测」**：先 GET `feed/space`（她自己的流），非 JSON/412 → 今日不发，草稿留 pending。成本一次读，避免两次写撞墙。
2. **写窗口错峰**：图文发布只落在本地 20:00-23:00 的随机分钟（她现有作息尾段）；412 高发时段（晚 8 点整点前后）避开整点。
3. **发前「热身」序列**：发布前 2-3 分钟走一次正常读链（feed→debrief 任一），让写请求出现在读流里——这是浏览器行为的自然形状。
4. **退避纪律**：撞 412 后 `until` 内**所有动态域写一律不试**（traffic 已强制），把「下次尝试」设为 ≥24h 后的清晨，而不是 30 分钟——IP 级限流恢复以小时/天计（假设 H3；验证法：记录每次 412 与后续首次成功的间隔分布，数据在 `api-requests.log`+`traffic-state.json`，跑两周即可判）。
5. **旁路表达**：412 期间改用**不同业务域**的表达：私信主人（web_im 域）、收藏点赞（fav/archive 域，10-31 均正常）——「发不出动态的她今天多收藏了两条」比「反复撞墙的她」更像活人。专栏域是否幸免待验证 V1。

### 2.4 发布失败时她该怎么表现（人格规格）

像人地接受，一次说清，不轰炸：
- **当晚对主人**（私信或面板回执，一条为准）：「今晚的动态没发出去，B 站把我拦在门外了。稿子我留着，明天再看看。」——不抱怨技术细节、不请示重试。
- **私人日记**留一行判断（她已有的习惯），例如对风控窗口的主观感受；公开日记「想说」保留那条没发出的内容本身（内容不消失，只是没送达——这是「活过来」的关键叙事）。
- **禁止行为**：自动重试、把多次失败并成多条消息、追问主人「要不要再试」、当天反复 `dynamic recent` 刷屏（复核一天一次足够）。
- 现有代码已具雏形：TrafficError 文案直白、sending 状态机防双发、失败草稿 failed 可重试——缺的是**人格层把「今天不试了」变成她的决定**，建议在 ORIENTATION 增补一条（文案级改动，观测期后）。

## 3. 视频/声音上线的正确顺序

现状：V1 本地出片通过（20s/1080×1920，MiMo TTS 音色茉莉 + CC0 BGM AERIS，双封面），**未接发布、未投稿**（CURRENT 2026-10-30 实测）。B 站没有独立「音频投稿」给普通 UP（音频区历史上传通道面向老音乐人，待验证 V5），所以「她的声音公开」= 视频投稿一条路。

**三步走，每步一个人工闸门，顺序不可压缩：**

1. **第 0 步（无风险）**：World 出 `bili_video` 工具，**本地出片+面板预览给主人**——ROADMAP §3-C 已排（M3c 前半段）。验证内容质量与素材合规（CC0 BGM ✓；封面若用溟月形象须署名+NC 检查：B 站创作激励/充电对 NC 素材属「商用」灰色，视频不开激励即安全）。
2. **第 1 步（人工网页首发）**：主人登录创作者中心，**当面**替她投第一条（她出全部物料：标题/简介/标签/声明勾选，人不碰剪辑）。目的不是发布，是**实测**：新号视频审核时长、AI 声明选项与文案、首发流量反馈、投稿域是否也吃 412。全程不写一行新代码。闸门：主人操作+出镜责任在平台侧落在账号实名人。
3. **第 2 步（发布器，路线已因 2026-01 律师函事件改写）**：~~API 逆向投稿器~~ **否决**——bilibili-API-collect 因「协助规避风控」律师函永久关停后，视频上传这类最重的逆向写行为不应再自动化（详见 §6-2）。双轨替代：a) 申请**哔哩哔哩开放平台 OPEN API**（官方含视频稿件发布/删除/查询能力，资质门槛与个人可申性=V7）；b) 批不下来则**永久保持「她出全部物料、主人网页代投」**。无论哪轨，闸门不变：每条视频独立审批、kill 覆盖、日 ≤1 周 ≤2、AI 显式+隐式标识必选（法定义务，见 §6-1）、素材清单随稿归档（溟月署名审计）。
- **AI 标识策略（合规红线，2026-11-01 联网核对后升级）**：《人工智能生成合成内容标识办法》2025-09-01 施行，显式+隐式标识是**法定义务**且禁止删改隐匿——「正文不出戏」裁决需要主人重新圈边界（建议：让「我是 AI」成为她台词的一部分，披露即人设，不出戏与合规共存）。

## 4. 30 天平台节奏表建议（不刷量前提下的「真人 UP」基线）

参照系：粉丝 0-2k 的助眠/ASMR 图文+音频小 UP 的普遍行为密度（假设 H4：单样本社区经验，验证法=观测期内用 `feed`/`search` 对 5 个同类 UP 做只读采样，统计其 30 天动态/视频/回复分布）。

**真实频率基线（映射到她的开关）**

| 通道 | 真人基线 | 她的配置 | 现有开关对照 |
|---|---|---|---|
| 图文动态 | 3-5 条/周，**每周至少 2 天完全沉默** | draftMode=review 起步；观测后开 auto 也 ≤1 条/日、周 ≤4 | `draftMode`/`autoDailyCap`（dev 分支，ROADMAP §1） |
| 视频 | 2 条/月起步（小 UP 常见月更） | 第 3 节走完第 1 步前 = 0 | 无视频发布器（天然闸门） |
| 评论回复（别人评论她动态下） | 每天集中 1-2 个时段扫一次，逐条回 | comment 走待审队列；回评优先级>新发评 | go-gate 已就位 |
| 点赞/收藏 | 零散、每天各 ≤5，多在「浏览后」 | 已限：fav 3/日、like 30 天去重 | 自发档（PERM-TIER） |
| 私信 | 随时（只和主人） | 直发 | tierDmReply=direct |
| 公开评论（主动出击） | 真人小 UP 也做，但低频 | 待审队列、**≤2/日** | 裁决已限 |

**30 天日历草案（11-01 起，观测期 14 天只跑现有配置）**
- 第 1 周（观测期）：只发已放行图文稿 ≤4 条；每天一次 `dynamic recent` 复核；412 则按 §2.3 旁路。零新能力上线。
- 第 2 周（观测期）：同上。另做两项**只读**研究：同类 UP 频率采样（H4）、专栏/热搜端点 dry 探路（V1/V4）。
- 第 3 周（观测后）：上线置顶评论 + 定时发布（§1.2，两个 0.5d）；专栏首发 1 篇（人工放行如动态）；开 draftMode=auto 试跑（cap 1/日、周 4）。
- 第 4 周：视频第 0/1 步（本地出片接 World + 主人网页代投首发）；复盘 412 频次/空日/互动真实性，对齐 K4 体验项。

## 6. 联网核对结果（2026-11-01 回填）

1. **AI 标识是法定义务，不止平台复选框（V2 已证实，且升级风险）**：《人工智能生成合成内容标识办法》（网信办等四部门）2025-09-01 施行——所有 AI 生成文字/图片/音频/视频须**显式标识（用户可感知）+ 隐式标识（元数据）**，平台自动检测补标，**严禁删除/篡改/隐匿标识**，违者按社区规则+法规处置。B 站侧实例：AI 创作大赛规则明确「AI 内容须显著区别于真人实景，不得模糊混淆」。
   → **对现行裁决的冲击**：ROADMAP §3-E「正文永远不出戏、披露只进简介」在纯图文动态或还可辩护，但**视频/音频投稿必须有可感知的显式标识**（片头角标/简介首行/平台声明勾选三选二）。这是合规硬线，不是风格选项——需要主人重新拍板「不出戏」的边界（建议方案：人设内自指「我是 AI 小鱼」的文案，把披露做成角色魅力而非出戏）。
2. **bilibili-API-collect 已因律师函永久关停（2026-01-28，V6 已证实——最大新增风险情报）**：B 站委托律所向该 2 万星仓库发函，指控其文档「通过技术手段规避/破坏平台风控措施」，维护者删库停更。含义：
   - 整个逆向写接口生态处于 B 站**法务重点打击射程**；她的工具链（全部 web 端逆向接口）技术上是既成事实，但**写频率一旦像机器，风险从「412 限流」升级为「封号乃至法务」**。这从法律维度佐证了「低频、人味、人工闸门」不是保守而是必需。
   - **视频投稿不要走逆向 API**（上传链路是最重逆向行为，恰是律师函指控核心）。官方出路是**哔哩哔哩开放平台 OPEN API**（含「视频管理：稿件发布/删除/查询」），但有开发者资质审核门槛（待验证 V7：个人开发者可否申请稿件发布权限、审核周期）。
   - §3 三步走中第 2 步改为：优先申请官方开放平台；不批则**永久保持「主人网页代投」为唯一视频发布方式**（她出物料，人出手指——本来就是最像「团队」的形态）。
3. **专栏已并入「图文/Opus」体系（V1 修正，旁路假设弱化）**：B 站专栏功能改版为图文并与动态混合（`member.bilibili.com/read/editor` 旧编辑器已下线，文章落 `bilibili.com/opus/`——她 verify/mention-check.mjs 已在读 opus 页）。推断：长文投稿与动态发布**大概率同走 polymer/opus 写域**，「专栏域可作 412 旁路」不成立或价值大减；长文价值仍在（搜索长尾+深度内容），但 412 旁路只应指望**跨业务域**（web_im/fav/archive 实测 10-31 正常）。验证法 V1b：412 窗口期只做一次人工网页发 opus 长文，观察是否同样被拦（人的手，零代码）。
4. **412 社区共识与自家代码互证（H2/H3 佐证）**：多方总结触发因子=请求头过于冗余或不一致、频率、认证信息、IP 环境；解法=精简且**稳定**的请求头、指数退避、（海外代理池——她不需要）。`bili-api.mjs` 的 300ms 节流+5→30min 熔断+缓存三件套与最佳实践一致；缺的是 H2 的统一指纹与 H3 的「按天退避」策略，见 §2.2/§2.3。-352 为 WBI 签名/风控新增码，traffic 已列入熔断集合（代码 `BAN_CODES` 实测含 -352 ✓）。

**回填后的优先级变化**：视频投稿由「最高价值」降为「官方开放平台或人工代投双轨，逆向 API 路线否决」；置顶/定时发布/关注关系读取等低风险接线不受影响，仍是下窗口首选；AI 显式标识问题升级为**发布视频前的第一个待主人拍板项**。
