## 3. 把关链（唯一宿主级机制）

判据：**换一个宿主/换一个人格，它是否还得一模一样存在。** 只有一处通过：

**「同一语义不得有第二份实现」**。事故证据：2026-11-01 01:23 正式配置 `publish.draftMode`
被同机一个盲 POST 改成 `auto`（载荷带 `autoDailyCap=-9`），7799 是免口令端口。
kill 的物理约束是"漏点 = 不可逆"；`write-refusal.mjs:46-47` 已实证重复记账会让分母翻倍。

**可以分散的**（不要写成物理约束）：内容判据（理由够不够长）、频率节奏（一天几条）、纪律闸
（收不收回）、正文清洗。

目标接口（把关链席给的形状，落地时按此写）：

```ts
export interface WriteGate {
  check(action: WriteAction): Promise<GateVerdict>
  enqueue(action: WriteAction): Promise<{ ok: true; pendingId: string } | { ok: false; reason: string }>
  release(pendingId: string, opts: { token: string; actor: 'cli' | 'host' }): Promise<ReleaseResult>
}
```

退出码统一：**0** 成功（且输出无 `✗`）· **2** 闸门拒（可重试或改配置）· **3** 前置缺失（凭据/关系）
· **4** 传输层拒（冷却/风控/登录态）· **5** 素材不合法 · **6** 平台拒（code≠0）· **-2** kill。
账：成功 `<kind>`，失败 `<kind>-failed` + 字段 `stage: 'gate'|'platform'|'transport'`；
**补齐** `comment`/`danmaku`/`dynamic` 三条成功账，否则"今天发了多少"算不出来。
账里不许出现正文/凭据/token。

## 4. 这一轮不做（写下来，免得又被当成忘了）

- 不开 14 天观测窗（主人已定）。

  追加 600 行实测无撕裂，所以 `causal` 不需要锁）。

  现值等于"当日不限条数"，`traffic.writeDaily=30` 仍是硬上限，所以不是完全失控；
  要收紧的话改成 3 即可（对齐 `shareDaily=3`/`selfDaily=6`），这是**建议不是结论**。
