## 2. 插件生态对照：我们不是没接，是接的方式不同

主人列的每个插件，在我们 BLUEPRINT 里都有**已核实的接入点**（不是空话，是 REUSE-MATRIX 实测过许可/耦合的）：

|---|---|---|

**"分发安装怎么就不行了？"** —— 能。两条路都开着：
1. **DSH 插件本体**（dsh-bili-whale）本来就是标准 DSH 插件，`dsh plugin add` 可装，面板可配；
2. **Q-08 允许 DSH sidecar 跑视频/语音**（选项 B），Q-04 允许视频插件接入（选项 A）——这两个 NEED-USER 不是"不行"，是**等你拍板时机**。团队建议 A（M4 后先视频），没敢替你开是因为每个插件会引入第二宿主/计费/输出目录未知数（PLAN-REVIEW §12 的 `bili-op` 源码未解包问题）。

**你说"本身我们不也是用别人的这些东西吗"** —— 完全对。Cortico 本身就是 fork 的 MIT 框架，AMpath 的纯函数在抄，Edge-TTS 是第三方的，bili 协议实现参考了开源 bili-cli。我们的仓库里没有一行"从零发明轮子"的骄傲，REUSE-MATRIX 记了 40+ 个评估过的外部件。

## 3. 强加的约束：这次全撤了

| 约束 | 状态 | 理由 |
|---|---|---|
| **每日行动 ≤3 次** | **已撤**（rhythm.ts `MAX_ACTIONS_PER_DAY = ∞`，commit 912c046） | 发明的作息。10 天模拟：无上限后日均 2.7 次，欲望+体力自然收敛，不会刷屏 |
| **两次行动间隔 2.5h** | **已撤 → 40min**（同 commit） | "缓一缓"合理，排班表不合理 |
| **夜间窗口 / 定时唤醒** | 早已撤（clock.enabled=false, windows=[]） | 同类发明 |
| **21:30 nightly-scheduler / HKCU WhaleDraft** | 早已删 | 同类发明 |
| 流量预算 readHourly 600 / writeHourly 12 | **保留** | 这是 B 站风控断路器（412/-352 疼觉），不是 token 预算；600/小时根本打不满，实测读 30/天 |
| maxWakesPerDay ≤12（DSH core 校验） | 留 | DSH 时钟已整体停用，这参数是死配置 |
| 审批门 + 一次性 token | **保留** | 主人 10-28 定的"人按发布键"，是产品本体 |
| kill switch / --force 撤销 | 保留/DECIDED-NO | 同上 |

**"不缺 token 让他多运动"** —— 已生效：上限撤了、间隔缩短了、体力恢复速率 0.005/h 保持（冬眠机制本身在）。10 天模拟日均 2.7 次、无失控日。想更活跃还可以调体力恢复或 CHECK_PROB，但先看撤掉 cap 后的真实行为再动，一次改一个变量。

## 4. 剩下的"约束"其实是产品

- **审批门**：你 10-18 选的 B 档"发前审核"，10-28 重申"人按发布键"。
