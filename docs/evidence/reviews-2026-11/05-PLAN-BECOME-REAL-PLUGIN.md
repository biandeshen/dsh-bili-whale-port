# 怎么变成真正的插件 · 两条目标要分开

> 主人问"到底怎么样能变成独立的、插件的形式"。本文先把**现状体检**做实，再把两个经常被混为一谈的目标拆开，最后给可验收的路线。**排队位置**：specs 补齐（#3）→ 旧三代清零（#5）→ 本项（#6）。

## 一、现状体检：最难的那关你已经过了

实测（本会话自己跑，非引用）：

**成立的部分（比我自己上一条说的更好）**
- `packages/cortico-adapter/src/*.ts` 里 **import 语句 0 条** —— 它是纯类型 + 纯 helper，不反向依赖任何宿主。
- 面板拿 UI 是**注入**的，不是 import 的：`PanelCtx` 携带 `ui`，helper 一律收 `ctx: PanelCtx`（`cortico-adapter/src/webui-helpers.ts:55`、`:73`、`:104`）。
- 契约本体 `XiaoyuCapability` 在**你这份** `persona-core/src/capability.ts`，明写三条铁律：能力包平级实现本接口；**能力包内部严禁 import `cortico/*`**；每个能力包必须同时声明 store + context/event + tools + panel（不许有只读黑盒）。
- 能力包与转接头代码里**搜不到任何直接发起模型调用的地方**（`core.complete/chat/llm/generate`、`invokeModel`、`submitMessage` 全 0 命中）→ 模型由宿主发起，她只提供上下文与工具。这一条做对了，插件就不该自己抓 LLM。

**结论：接口纯度 = 已达标。剩下全部是"装载层"问题。**

## 二、必须拆开说的两个目标（这是你被绕住的地方）

| | 「换底座」 | 「换机器」 |
|---|---|---|
| 问的是什么 | 不跑在 Cortico 上，还能跑吗 | 拷到别人电脑能装起来吗 |
| 属于哪类问题 | **接口**问题 | **打包 / 路径 / 依赖**问题 |
| 现状 | 基本已成立，只差下面第 1、2 步 | 完全不成立 |
| 具体阻碍 | 内核双份；没人跑过第二个底座 | `extensions/package.json` 写死 `link:E:/…`；`build-webui.mjs:24` 借宿主 `node_modules/esbuild`；`@xiaoyu/*: workspace:*` 声明了但代码零处使用（全靠 `../../peer/src/x.ts` 深链）；无 `engines`，Node 20+/22+/22.15+ 三处口径互斥；状态根 6 个键新旧两家分叉且门禁 EXIT=0 放行 |
| 跟你今天踩的坑有关吗 | **有**（402、`maxTokens` 空转、`gitSha` null 全在宿主层） | 基本无关 |

**我建议你只做左列。** 右列是分发给别人时才需要的成本，现在做了不解决任何一件你今天遇到的问题。

## 三、「换底座」的四步，每步都能证一件事

**第 1 步｜内核唯一化（收益最大，也最需要你先点头）**
`Cortico-up/persona-core/src`（16 个 .ts）与 `packages/persona-core/src`（21 个 .ts）两份同时被解析，15 文件字节级不同，契约本体只在你这份里。
- 判据：删掉/停掉宿主那份后，全量门禁仍绿、7799 行为不变。
- 代价说清：宿主仓是 `Pal-AI-Lab/Cortico` 的 fork（作者 Phant，你有 233 次提交），删它的目录要么在你 fork 里长期背着差异，要么去说服上游。**这是本路线唯一一处要碰别人仓的活，需要你先选：fork 里删 / 提 PR / 暂时只做"解析优先级"让引擎永远选中你这份。**
- 做完能证明：底座不再自带一个她的版本。

**第 2 步｜把契约面写成一份能读的接口文档（不是代码注释）**
`XiaoyuCapability` 要求宿主提供什么，今天只散在注释和 `cortico-adapter` 的类型里。收成一份宿主侧接口清单，预计 **4 件事**：模型发起、面板挂载点、状态目录、定时器。
- 做完能证明：换底座要写的东西是**可数的**，不是"改 18–20 处"这种黑话。

**第 3 步｜写一个 stub 宿主（本路线唯一的真验收）**
一个刻意极小的宿主（预估 150 行上下），只实现第 2 步那 4 件事，把六个能力包 + bot 装上去。
- **Definition of Done（不可协商的一条）**：stub 宿主上跑满 24 小时，`outward-evidence.mjs` 能拿到退出码 0（至少一次真实对外凭据），且 11 个页签里至少「她的一天」「作息遥控台」「待放行队列」三页可用。
- 做不到就承认：**"插件形式"至今未被任何一次运行证明过**，然后按第四节收口。

**第 4 步｜门禁补一条，防它再次长回来**
`check-live-drift`（或新门禁）加两条：能力包出现 `import 'cortico/…'` 即红；宿主侧新增未登记接口即红。

## 四、如果你不想投入第 3 步（这是完全正当的选择）

那么就该**把宣称降级**，而不是留着当口号：
- 文档里"万物皆扩展 / 可装到任何底座"改成实话：**"Cortico 上的一等公民；接口已宿主无关，但只有一个真实宿主被验证过。"**
- 这件事跟 specs 改制是同一刀，顺手就能改，成本一天。

**我不建议留现状。** 现状是最坏的：宣称还在，于是一有新的底座需求，团队就去补一层"其实还要改 18 处"的隐性成本，而你永远不知道边界在哪。

## 五、需要主人点头的只有两件事

1. **要不要做第 3 步那个 stub 宿主**（做 = 左列目标成立；不做 = 走第四节降级宣称）。
2. **第 1 步内核归一走哪条路**：在你 fork 里删 / 给上游提 PR / 暂时只锁定解析优先级。

第 2、4 步不需要决策，是纯执行。旧三代清零（#5）必须在第 1 步之前完成，因为 `core/`、`tools/` 里那些仍被引用的文件正是双内核的来源之一。
