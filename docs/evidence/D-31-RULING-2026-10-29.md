# D-31 裁决：feed 质量下限被「多偏好命中」绕过

- 日期：2026-10-29（逻辑日 10-28）
- 议题：feed 候选里混入播放 1 / 弹幕 0 的碎屑，是否修、在哪层修、要不要新阈值
- 团队：六席（架构 / 证据审计 / 产品体验 / 平台风控 / 挑刺 / 裁决），全部只读调研
- 结论：**团队可决部分已落地**；**新增阈值部分挂起，交主人（Q-10）**

## 1. 事实（无争议）

| 事实 | 证据 |
|---|---|
| 下限 `play<300 && dm<3` 是 2026-10-22 加的，当时同时留了「命中 ≥2 偏好词免检」 | `tools/commands/feed.mjs` 10-22 注释 |
| 免检口子被真实绕过：10-28 她看到的片子播放 1 | `~/.dsh/whale-diary.md` 10-28「播放是1」「我看的不是视频，是标题」 |
| 排序从未使用播放量（10-20 主人否掉的是加权） | `scoreOf = 密度×3 + 命中×4 + 反馈×2.5` |
| 免检不是主人拍板的规则，是 10-22 我们自己加的 | 代码注释只写「那可能真是小众宝藏」，无主人记录 |

挑刺席还指出：她原话后半句是「没人验过的东西，我不打分——这是我这几天唯一没做错的地方」。所以「判断退化成读标题」是推断，不是她的自述；这条已写进风险。

## 2. 六席意见摘要

| 席 | 立场 | 关键理由 |
|---|---|---|
| 架构 | 下限放 feed 准入闸，不进 `scoreOf`、不进 world/prompt | `feed.mjs:257-262` 把「垃圾判断」和「命中≥2」揉进同一布尔；world 层只透传，二次过滤会产生两套阈值 |
| 证据审计 | **部分成立** | 机制属实；但「连续多天播放1」被夸大——10-27 是 117/221/4，只有 10-28 是 1；且无候选池快照，无法统计低播放占比 |
| 产品体验 | 按「有没有人验过」（弹幕/评论>0）作**二值门**，不作序 | 全滤低播放＝只看爆款，失真；现状＝读标题空转；「验过」最贴近她自己的判据 |
| 平台风控 | 建议硬下限，但关注流必须豁免 | feed 的过滤全在本地，不会多翻页；`dm>=1` 会误杀关注源（其 dm 恒 0） |
| 挑刺 | **现在不该修**；要修就删免检口子，不加新数 | 她没受害；候选只 3–9 条、选片本在她手；`play>=50` 与 10-20 否决同类；观测前改 feed 会污染基线 |
| 裁决 | 删免检口子＝团队可决；`play>=50`/`dm>=1`＝需主人 | 300/3 已有；G3b 首日窗口 10-31，须在此之前合并 |

## 3. 裁决

**团队可决（已实施）**

1. 删除「多偏好命中 ≥2 免检」。质量下限对搜索/热门/排行统一生效。
   - **没有新增任何数值**：300/3 是 10-22 既有规则；这是收回我们自己加的例外，不是新判据。
   - **关注流豁免**：`kw === '关注'` 直接保留——她订阅的人发的新片播放再低也不是平台碎屑（风控/产品两席一致）。
2. 判定抽成纯函数 `tools/lib/feed-quality.mjs`（`keepCandidate`），`feed.mjs` 真正调用它；契约测试锁住「播放 1 + 双命中 → 丢」「关注流例外」「热门/排行无第二条通道」。
3. 新增**候选快照**：`~/.dsh/bili-whale/feed/<day>.json`，记录每条候选的 bv/标题/UP/播放/弹幕/命中/得分/keep/why。只读字段、无凭据。补的是审计席指出的证据缺口。

**挂起（Q-10，需主人）**

- 是否引入「验过」二值门（`dm>0` 或评论>0）作为**准入**条件；若引入，关注流同样豁免。
- 主人 10-20 否掉的是「播放量进入排序」，还是「任何播放量门槛（含准入）」？两种解读会导出不同答案。
