# C2 验收口径裁决 · 2026-10-29

> 议题：canary「长时间离线/关机」是否可以用替代方案验收。
> 输入：`~/.qoder/tmp/CANARY-DECISION/runtime.md`（运行时组）、`contrarian.md`（挑刺组）。
> 裁决人：组长。规则：以代码/实测证据为准，分歧留档。

## 双方的结论

| | 运行时组 | 挑刺组 |
|---|---|---|
| 能否替代 | **能**，但条件要改 | **不能**用 30 分钟替代 |
| 最短离线 | **≥26h，且跨 04:00** | **≥8h，且跨 04:00** + 一次强制终止 + 时钟回拨 |
| 依据 | `days>=1` 记忆衰减、`silentDays>=1`；30 分钟 < MIN_GAP 2.5h | 睡眠/关机同形、断电半写、日界双轨、`nextCheckAt` 不补算、时钟回拨 |
| 订正 | `COUPLING_CAP_MS` 实际是 **12h**（`decay.ts:70`），文档写 24h 是错的 | 同左（已修文档） |

## 裁决

**采纳挑刺组的门槛作为 C2 阻断条件：**
1. 真实关机 **≥8 小时**，且**跨过一次 04:00 日界**；
2. 期间有一次**强制终止**（`taskkill /f`）以覆盖半写窗口；
3. 恢复后跑一次**时钟回拨检查**（系统时间被调回过去时不产生永久 gap）；
4. `day-report` 用 `--expect-offline` **显式声明**预期 `missed/late`，不得默认放行。

**不采纳**"≥26h"作为阻断条件，理由：
- 26h 是为了触发 `days>=1` 的记忆衰减与 `silentDays>=1`，这属于 **M1 的记忆/关系机制**，不是 C2（离线恢复）的验收对象；
- 记忆衰减的 12h 封顶已有单测覆盖（`persona-core/tests/core.test.ts` 的 `simulateOfflineTime`）；关系沉默由 14 天观测自然覆盖（每晚都 ≥6h）；
- 把 26h 塞进 canary 只会把 G3b 推迟一天，而不增加对"离线恢复"的判别力。

**留档反对**：运行时组主张 26h；理由如上，不采纳为阻断，但列入观测期的非阻断观察项（若出现跨天记忆/沉默异常，再升级）。

## 执行方式（现在不能做）

C2 需要真实关机 ≥8h，不能在会话内伪造。执行步骤：

1. 关机前记录：`date`、`life.json` 的 `lastCheckAt/actionsToday`、`fields.json` 的 `lastAppliedAt`；
2. 关机 ≥8h（自然过夜即可），期间不启动任何服务；
3. 开机后先跑 `node scripts/day-watchdog.mjs --once`（触发 audit + 补 tick）；
4. 跑 `node scripts/cortico-health.mjs`（5 项必须全 ✓）；
5. 跑 `node scripts/day-report.mjs --date <离线日> --expect-offline`，除 `missed/late/tick-gap` 外不得有 FAIL；
6. 检查 `ticks.jsonl` 末行可解析、无重复行动（`actionsToday` 不因恢复暴涨，单日 ≤3）；
7. 记录到 `docs/evidence/D5-CANARY-2026-10-29.md`。

### 预演结果（2026-10-29，临时 home）

用临时 home 造了一个"离线日"（`missed/late` + tick 间隔 840 分钟 + 有 diaryHash 的草稿）：

```
严格模式：exit=1，flags "unexpected: missed,late"，tick 间隔 FAIL
--expect-offline：exit=0，flags "expected: missed,late"，tick 间隔 PASS（expected: offline）
DRILL PASS
```

**预演抓到并修掉一个会让 G3b 卡死的 bug**：`--expect-offline` 原先只放行 `missed/late`，但离线必然导致 `tick 最大间隔 >90` 判 FAIL。现在 `--expect-offline` 同时放行 `tick-gap`，`expected.json` 的 `allowFlags` 也支持 `tick-gap`。

### 每日作业演练（2026-10-29）

`node scripts/day-watchdog.mjs --daily-jobs --at <ISO>` 可在任意时点补跑"前一天反事实 + G3b 审计"（不启动循环）。临时 home 演练：

```
counterfactual: { ok: true, diff: 6, day: '2026-10-28' }
g3b: { day: '2026-10-29', ready: false }
DAILY JOBS DRILL PASS
```

演练抓到 `g3b-status.json` 的 `day` 被 g3b-check 输出覆盖（按真实 now 而非触发时点），已修正字段顺序。

## 通过/失败

- **PASS**：1–7 全部满足；`missed` 至少一次为真（证明审计生效），且除预期 flag 外无失败。
- **FAIL**：出现重复行动、`actionsToday>3`、ticks 末行损坏、`lastAppliedAt` 倒退、或恢复后 60 秒内无 tick。

## 执行方式（工具化，2026-10-29）

关机前：

```bash
node scripts/c2-offline.mjs arm
```

- 记录 `control/c2.json`（armedAt、baseline）；
- **事前**给 D0/D1 写 `days/<D>/expected.json`（`missed/late/tick-gap`，标 `requiresC2Result:true`）。

开机后：

```bash
node scripts/c2-offline.mjs verify
```

依次检查：arm→now ≥8h、**tick 时间线里的最大空窗 ≥8h 且这段空窗跨 04:00**、health、两天的 `day-report --expect-offline`、ticks 末行可解析、`actionsToday ≤3`；通过则写 `control/c2-result.json` 并把 `control/canary.json` 的 C2 置 pass。

**2026-10-29 补强**：只看 arm→now 会把“arm 了但服务一直跑”误判成离线。`verify` 现在从 `days/<D>/ticks.jsonl` 找最大空窗（`tools/lib/offline-gap.mjs`，测试 4/4）；空窗不足 8h 或没跨 04:00 直接 FAIL，即使用户忘了关机也不会假通过。

**防作弊**：`expected.json` 只有在 `c2-result.ok=true` 时才放宽 `day-report`——只 arm 不关机的日子仍会判 FAIL。演练已验证（arm → 伪造 21h 窗口 → verify PASS，且 verify 前无 flag 报告仍 FAIL）。

## 时钟回拨检查（已做，2026-10-29）

预演时发现两处会在回拨时出问题的真缺陷，已修并加单测：

1. `rhythm.decideAction` 的间隔门：`now - lastActionAt < MIN_GAP_MS` 在 `lastActionAt` 未来时是负数，会永远判"还没到" → 她可数天不行动。改为**负间隔不算 gap**。
2. `personaAdapter.applyEffects` 会把 `lastAppliedAt` 写成 `now`（回拨时倒退）→ 下次重复结算同一段时间。改为 `max(now, prev)`。

测试（共 31 项全过，`tsc` 0）：

```
persona-core: '时钟回拨：lastActionAt 在未来时不被间隔门卡死'
World:        '时钟回拨：applyEvent 不把 lastAppliedAt 倒退'
```

代码事实：`applyEffects` 的 `elapsedMs` 与 `lifeTick` 的 `hours` 都用 `Math.max(0, …)`；`simulateOfflineTime(f, -5)` 断言不变。
