# D-36 唤醒语把 ORIENTATION 变成可选 —— 团队裁决与更正（2026-10-29）

> **更正（同日 09:42）**：最初只看两次唤醒，误判成“自然唤醒从来不出稿”。用 `scripts/wake-audit.mjs` 回放完整会话后确认：
> 10-26 23:29、10-27 11:39、10-28 01:12 都走完了流程并出了草稿；15:49 与 22:21 两次跳过，**都发生在当天已有草稿之后**。
> 所以缺陷仍在（唤醒语允许整轮不做），但不是“她不会出稿”；它影响的是“当天还没有稿时，她可能只看不写”。

## 2. 六席裁决（基于更正后的事实）

| 席 | 主张 | 结论 |
|---|---|---|
| 产品席 | “看”是生活，“发”是表达。看的部分应每天发生；发可以拒，但要留下原因 | 采纳：看强制，草稿默认、可拒须留原因 |
| 架构席 | 只改提示词，不动工具门禁与场值；三闸保持 | 采纳 |
| 运行席 | 15:49 跳过 debrief 与 feed 质量差有关（播放 1）；D-31 已改善，需看下一轮 | 采纳：feed 质量作为前提观察 |
| 安全席 | 不放松任何写操作；草稿仍只入队 | 采纳 |
| 挑刺席 | 改提示词不保证遵守；应加工具级 `[NEXT]` | **部分驳回**：先用 `wake-audit` 观察一轮；仍跳再上 D-36b |
| 记录席 | “改了提示词”不是证据；必须看真实工具序列 | 采纳：D-36 在自然唤醒前不关闭 |

## 3. 改动

| 位置 | 改后 |
|---|---|
| 行动事件末尾 | `这一轮先看：mood_read → traffic → feed → debrief → 读/写当天两本日记。这几步不能跳。` + `看完再决定要不要出草稿（第 6 步）；今天已经有稿就不要再出。不想发，就在私人日记里写清原因。` |
| 活动列表 | `看完还有余力，可以再挑一件小事` |
| ORIENTATION 第 6 步 | 补：`今天已经有稿就别重复出；实在不想发，就在私人日记里写清原因。` |
| 新工具 | `scripts/wake-audit.mjs`：从会话记录还原每次唤醒的工具序列，判定完整/缺什么；`--strict` 用于验收；`tests/wake-audit.test.mjs` 3/3 |

没有改：工具参数、写操作审批、`canDraft`/`diaryFresh` 闸、feed 预算、节奏阈值。

## 4. 验收（下次自然唤醒）

```
node scripts/wake-audit.mjs --last 1 --strict   # 最近一次不完整则 exit 1
```

- 当天**没有稿**：应出现 `mood_read → traffic → feed → debrief → 日记 → draft_dynamic`；若只写日记不 debrief → D-36 未修好，上 D-36b。
- 当天**已有稿**：允许不看片（她可以只记一笔），不算失败；但“看”的步骤若发生则不应跳过 debrief。
- D-36 关闭条件：一次“当天无稿”的自然唤醒走完 feed→debrief→草稿，或私人日记里明确写“不发+原因”。
- 不把“提示词改了”算通过；不算 G3b 证据。
