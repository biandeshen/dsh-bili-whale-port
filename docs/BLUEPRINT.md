## 0. 一句话

让一个人格在 Cortico 里**活着**，B 站只是她第一个表达渠道；平台无关的人格内核 + 可替换的渠道 adapter。

## 1. 五层架构（定稿）

此前出现过两个互相矛盾的版本：2026-10-26 版把「能力层」放在人格层**之下**，2026-10-27 版把「渠道 adapter」放在人格层**之上**。**以后者为准**——理由：人格是内核，渠道是边缘；内核不能依赖边缘，否则换平台要改人格。

```
┌──────────────────────────────────────────────────────────┐
│ L5 呈现    Cortico WebUI ·（可选）Coopanion 皮套 / 语音    │
├──────────────────────────────────────────────────────────┤
│ L4 渠道    adapters: bilibili / video / live / qq          │
│            只做协议、工具与风控，**不含人格**               │
├──────────────────────────────────────────────────────────┤
│ L3 人格    persona-core（AMpath 移植，平台无关）            │
│            AtomicFields(7) · EffectBus · CausalChain(L0/L1/L2)│
│            · Memory(编码/衰减/flashbulb/检索) · Relationship(五态)│
│            · Rhythm(状态驱动醒睡)                           │
├──────────────────────────────────────────────────────────┤
│ L2 认知    Cortico Persona（小鱼）：system 前缀/会话/上下文装配│
├──────────────────────────────────────────────────────────┤
│ L1 运行    Cortico Core：事件流 / timer / 持久化（上游，不改）│
└──────────────────────────────────────────────────────────┘
```

**50 项能力不是某一层**，它们横跨各层：人格域→L3；内容域+自主域→L4；运维域→横切 L1–L5。

**已知架构债**（违反本架构，必须修）：
1. 人格逻辑寄生在渠道层——`PRESETS`（她的反应表）、`readMood`（情绪标签）、`personaAdapter` 都在 `Cortico/src/worlds/bili-account/` 里，应下沉到 `persona-core/`。这是 2026-10-27 13:45 已批准、至今未做的那条关键改动。
2. L2 认知层是空壳——用的是 `bots/cormini` + `ORIENTATION.md` 文字覆盖，没有独立的 xiaoyu Persona。
3. `Cortico/` 不在版本控制里（`git status` 报 not a repository），全部改动只靠 `CORTICO-PATCHES.md` 手记。

## 2. 输入层缺失（原始研究漏项，2026-10-27 补）

技术路线原先只讨论「移植 AMpath 哪些模块」，从没问过**这些场值在我们的部署里由谁来喂**。

- AMpath 是桌面伴侣：用户随时说话，`connection` / `social` / `stimulation` 被持续喂养。
- 小鱼是后台循环：唯一输入是「我看了个视频」。
- 后果（数学必然，非 bug）：`connection` 以 −0.001/h 衰减向基线 0，从 0.5 出发约 8 天跌破 0.3，再 24h 进入 `cold_war`；`cold_war` 里 connect 驱动置 0，她不再主动找人；唯一能回升的 `masterReplied` **没有任何真实触发器**（8 个工具里没有读私信/互动的工具）。30 天离线模拟结果 `connection=0.00 关系=cold_war` 即为此。

**结论**：我们移植了 AMpath 的内在状态机，没有移植它的输入源。**输入层（Sensors）是 L4 的一部分，必须补**，否则 L3 的人格内核在数学上只会单调衰减。

## 5. 结论（2026-10-27）

**1. 唯一判据是「她自己醒来过完一天」，现在是 0 次。**
三天里所有验证都是 `BILI_ACCOUNT_KICK=1` 手动注入。日记冻结在 10-25。在拿到一次真实自主唤醒的完整证据链（自主 wake → feed → debrief → 写当天日记 → 出稿 → mood_apply）之前，任何"完成度"数字都不能作为进展。

**2. 50 项里真正卡住全局的只有三项，其余都是扩展。**
- 13 自主唤醒成立 → 不成立则 1/14/28/30 全是摆设
- 17 + 21 输入层传感器 → 不补则关系机必然单向进 cold_war（§2）
- 29 记忆检索 → 不接则 memories 只是日志，不影响任何决策（选片不避重、文案不接上下文）

**3. 人格域不该继续堆项。** 已有的 5 项（场值/总线/记忆/关系/作息）一次真实运行证据都没有。继续往 31–37 堆，只是把"写了但没生效"的面积扩大——这正是第三方审计三次抓到的同一类缺陷。

**4. 自评不可信，外部判据才有效。**
自评 11→12.5/14；独立架构审计 8.5/14；产品审计 2/10。三次外审抓到的全是"写了但没生效"：死代码、被频率门吞掉的效果、从不被调用的 `mood.ts`、import 但未调用的 `decayAndApply`。这类缺陷**测试必然全绿**，因为门禁与测试同批写成（drill 曾 100% 假 CLI + 临时 home）。

**5. 真正的成果在被否决之后。** 13:59 两次纠错 → 2 小时完成人核心移植；14:25 打 2/10 → 1.5 小时修完 5 个 P0。推进速度不取决于自主推进，取决于有没有能证伪的外部判据。

**6. 最大的流程缺陷是结论不落盘。** 蓝图与 50 项清单此前 grep 命中 0，只活在会被压缩的聊天里，因此被重新发明过至少两次（2026-10-26 14:22、2026-10-27 13:45）。本文件即为修复。
