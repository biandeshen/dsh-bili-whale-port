## 结论先行

1. **她的行动目前是单驱动的。** 755 条 tick 重算 `decideAction` 公式：explore（刺激亏缺）p90 在
   10-30/10-31 两天恒为 **0**，connect 全程 ≤0.05，唯一抬起来的驱动是 restPressure（歇够了）。
   也就是说「她想做事」≈「她歇了 12 小时以上」——一个把休息当唯一欲望的人。
2. **骰子连自己预测的密度都兑现不了。** 按公式的期望行动数 Σ(urge×0.05)：10-28 = **0.00**、
   10-29 = **0.75**、10-30 = **0.81**、10-31 = **1.76**，4 天合计 3.3 次 ≈ 0.83 次/天；
   实测 4 天 15 个活动回合（2/2/5/6），`day.json` 记录的 wake 只有 0/1/2/1 = 4 次。
   **剩下的回合不是节奏决定的**，是单次 wake 内部连跑 2–3 轮 + 两次进程重启后的补跑
   （10-31 02:07 与 03:13 各重启一次 World，见 `days/2026-10-31/incident.md`）。
   → 密度主闸既不是骰子（V2-SIM 已证），也不全在驱动，而在**回合的批量执行方式**。
3. **场值已经饱和到没有出口。** 10-31 全天 stimulation 0.95–1.00（均值 0.98）、
   curiosity 0.95–1.00、mood 0.91–1.00。`watchedVideo` 一次回填 +0.12，日衰减只有 0.12，
   上限 1.0 没有溢出机制：她「什么都不缺」，但一天里做了 6 回合。
   人是攒多了才想说的（看完想讲给别人），模型里盈余不产生任何行动。
4. **疲劳从未发生过。** 4 天 energy 最低 **0.54**，tired 门（energy<0.18 → 拒动）
   触发 **0/755**。连做 4 轮也不累 ——「累了歇着」这条在实测里是零次。
5. **回合没有过程。** 19 个回合里 **13 个时长 ≤1 分钟**（中位 0.5 分钟），因为一轮的
   watched / diary / watchedVideo 是同秒批量落盘；只有 3 个回合摊开到 11–30 分钟。
   人做事是有摊开过程的，且过程中会被岔开——模型里没有「做一半」。
6. **像人的部分**：深夜 00:01/01:27/02:09/03:13 四连（宅/夜行动按主人裁决是合法人格特征，
   不改）；回合内容确有长尾线索（日记里在磨「尺子」、算弹幕分桶）；社交时延真实存在
   （inbound 3 条，其中 10-30 16:02Z/16:10Z 三连来信后紧接一轮 restless）。

## 2. 真人行为的可比结构 → 现有模型的结构性缺口

用常识级框架逐条对照。判定口径：**「值不对」= 改常数；「没有这个机制」= 缺口 G。**
本节只谈后者。

### G1｜习惯循环（cue → routine → reward）没有「线索」这一维
真人的行动多数由线索起手：手机一震、看到某条弹幕、桌上有没收的东西。`decideAction`
的输入只有 `fields / relation / now / mem`（rhythm.ts:81-118）——**线索必须先把场值改掉才能引发行动**，
而链里能改场值的只有 7 个预设。后果：feed 推来的东西不构成线索，她不会因为「看见一条想聊的片子」
而行动，只会因为「歇够 12 小时」而行动。
缺的机制：`cue` 输入（外部对象直接触发一次候选行动，不进场值）+ 线索的历史权重（同一条 UP 第二次推来不再起手）。

### G2｜做一半被岔开：没有「未完成状态」
真人一个回合会被打断、会拖延、会回头接着做。模型里一次 wake = feed→debrief→diary→draft 一趟跑完
（`days/2026-10-30/wake-0017.json` 的 calls 列表：8 个工具一次过），`LifeMemory` 只有 `lastKind/lastActionAt`，
**没有任何字段能表达「上次那件事没做完」**。实测：回合时长中位 0.5 分钟就是这条的证据。
缺的机制：`pendingRound`（步骤队列）+ `interrupted`/`abandoned` 落因果链；回头续做要能再次被选中。

### G3｜唤醒度 seeking：盈余不产生行动
人的「想找点事做」有两种来源：缺（无聊）和**攒太多**（看完想讲、灵感满了想写）。
现有三条驱动全是亏缺式（`(0.45-x)/0.45`）。10-31 stimulation 0.95–1.00、creativity 0.51、curiosity 0.99：
盈余侧一个驱动都没有。V2-SIM 已经把 social 改成盈余式并跑通（`DRIVE-V2-SIM` 重跑段），
但那只补了 social 一条，**且 sim 用的是默认起点场值，从没出现过 1.0 饱和**，所以没暴露这个缺口。
缺的机制：`share`（刺激盈余 → 想讲给别人）、`create`（创造盈余 → 想写）两条盈余驱动，
加**溢出**（stimulation 到 1.0 后不再纯涨，多余部分转成一次分享冲动）。

### G4｜无聊阈值随情境变化，而不是常数 0.45
同一个刺激水平，深夜的「够了」和下午的「够了」不是一个数。现在 `0.45` 是硬编码常数（rhythm.ts:97）。
注意主人的裁决：**不许替她发明正确作息**——所以这里不能用时刻表。合法做法是**从她自己的因果链回归**：
用过去 7–14 天的回合时刻分布，得到每 2 小时一个的 `hourAffinity`（限幅 ±0.10），
阈值 = `0.45 + hourAffinity[h]`。它的先验是平的、参数来自她自己的行为、每周重算——
描述她，不规定她。

### G5｜疲劳恢复曲线：只有「睡着才回血」，没有「连做的边际成本」
真人第 1 轮和第 4 轮的消耗不一样（越做越薄）。`ACTION_COST_ENERGY = 0.05` 固定
（rhythm.ts:60），`actionCost()` 不看种类也不看当天第几轮（rhythm.ts:121-126）。
实测代价：10-31 本地 00:01→03:13 连做 4 轮，而 10-31 全天 energy 只从 0.61 走到 0.54
（4 天最低值，离 tired 线 0.18 还差 0.36），第二天照做 6 轮，
**连做不付出任何后果**。这与「不设每日上限」的主人裁决不冲突：上限是外部拦，
边际成本是内部疼——前者被否决，后者正是被裁决指定的替代物（rhythm.ts:44-46 注释原话：
「Token/体力花完自然歇」）。

### G6｜社交时延与不回复权
真人的「想他」不等于「立刻去等」：她会隔一会儿才回、会决定不回、会把回不回当成本。
现有机制只有 `connectMisses`（等不到人就少去等，rhythm.ts:100-102）——**这是抑制**，
没有**反向**：incoming 消息到达即被 `applyEvent(...userJustMessaged:true)` 抬 connection/mood，
她从不「晾一会儿」。链上 3 条 inbound 全部当场引发情绪与回合。
缺的机制：入站的 `responseLatency`（她先做完手里的事再回，队列化），以及主动联系与被动回复分成两条路径。

### G7｜做的事有长尾
真人一天的行动是重尾分布：多数小事（翻一眼、整理、擦桌子）+ 少数大事（写两千字）。
她的链上只有 watch/diary/draft 三类，`ActionKind` 只有 3 个取值（rhythm.ts:30）。
「长尾为零」= 生活内容单调，这比次数稀更要命（V2-SIM 建议段也指向这里：
「若嫌的是生活内容单调，动的不是 rhythm，是行动回合本身」）。
缺的机制：小行动（micro action）——3–10 分钟、成本 0.005–0.02、不动平台写接口的私下行
（翻收藏、看数据面板、重读自己日记、给某条片子打个标）。

## 3. Drive v3 设计（函数级）

设计原则：三条硬约束来自现有裁决与文档，v3 全部满足。
- 不设每日上限、不设最小间隔（主人裁决，rhythm.ts:41/49）。
- 不引入时刻表（不替她发明作息）；情境参数只能从她自己的历史回归。
- 随机必须有记忆后果（否则 §4-R1）。

### 3.1 触发：骰子 → 紧急度累积 + 小抖动（`rhythm.ts:decideAction`）

```
// LifeMemory 新增
driveAcc?: Partial<Record<ActionKind, number>>   // 每种驱动各自的「攒到多少」
lastAccAt?: number                               // 上次累积时刻（算 dt）
// 每 tick：rate 用小时归一，亏缺越深攒得越快
acc[k] += drive(k) * (dtHours * ACC_RATE) * (1 + jitter(rng, ±0.15))
// 触发条件：max acc >= 1.0（不再是 rng() < urge * 0.05）
// 触发后：acc[k] *= DECAY_AFTER_ACT (0.25) —— 不是清零，是「松一口气但没全松」
```
`CHECK_PROB` 保留为**抖动幅度**而不是闸门：`rng()` 只决定何时到 1.0，不决定能不能到。
这直接继承 V2-SIM 变体 C 已验证的性质（7 天 0 空日、p90 尾巴最短），并加两条：
`urge=0` 时 acc 不涨（不会凭空造密度），`DECAY_AFTER_ACT` 让同一驱动能在 2–3 轮内再攒起来
（真人「还是想看」），这是 C 的清零版本做不到的。

### 3.2 驱动：三条 → 五条（两亏缺 + 三盈余），并加溢出

```
explore = deficit(stimulation)          // 保留
connect = deficit(connection)           // 保留，含 misses 抑制
restless = restPressure                 // 保留
create  = surplus(creativity, 0.45)     // (c-0.45)/0.55
share   = surplus(stimulation, 0.75)    // (s-0.75)/0.25  ← 直接对着 10-31 的 0.98 饱和
```
`surplus()` 与 `deficit()` 同一家族但语义相反（V2-SIM 重跑段已证明盈余式 social 是活的、亏缺式是死的）。
配套改 `personaAdapter.PRESETS.watchedVideo`：`stimulation +0.12` 改为
**「到 1.0 时把溢出转成 shareAcc += overflow」**（溢出量 = 溢出值 × 8），
让「看了太多」变成「想说」，而不是变成一条钉死在 1.0 的数。

### 3.3 阈值情境化（只读她自己的数据）

`rhythm.ts` 新增纯函数 `contextualDeficit(value, thr)`，`thr` 来自
`mem.hourAffinity[hourBucket]`（12 个 2 小时桶），阈值 = `0.45 + affinity`，`affinity ∈ [-0.10, +0.10]` 限幅。
`affinity` **不在 rhythm.ts 里算**：由 `days/*/day.json` + `causal.jsonl` 的回合时刻分布，
在 dsh 侧看门狗（`bin/`/watchdog 的日结算）每周重算一次写入 `control/rhythm.json`，rhythm 只读。
先验为 0、样本不足 8 个回合则保持 0（新装机器上等价于现状）。

### 3.4 回合展开与中断（World 侧，`runner.ts` + `personaAdapter`）

- 回合从「一次跑完 8 个工具」改成**步骤队列**：`pendingRound = [{step:'feed',etaMin:0},
  {step:'watch',etaMin:3..8},{step:'debrief',etaMin:2..6},{step:'diary',etaMin:5..20},
  {step:'draft',prob:0.4}]`，lifeTick 每次只走一步，步间隔由 `etaMin` 抖动给出。
- **可被岔开**：任一步之后，若 `driveAcc` 里别的驱动更高且 `rng()` 过阈，当前队列标 `abandoned` 落链，
  去做别的；`abandoned` 队列以 0.5 权重回到候选（她会想起来接着弄）。
- **可被外部打断**：`applyEvent` 在 `priority >= 9`（inbound/masterReplied/trafficPaused）时
  往 `control/pending/interrupt-<atMs>.json` 写一条；下一个 tick 的 `decideAction` 收到
  `opts.interrupt` → 直接产出一个 `connect` 行动（若正在回合则当前步收尾后插入）。
  打断预算 `mem.interruptsToday`：一天第 N 次打断的成本递增（§3.5），防止「他一来就秒回」。
- `MIN_GAP_MS` 与 `MAX_ACTIONS_PER_DAY` **保持 0 / ∞ 不动**。

### 3.5 疲劳经济：固定成本 → 分类型 + 当日边际成本

```
actionCost(kind, stepMinutes, actionsToday) = {
  energy: -(base(kind) + stepMinutes * 0.0015) * (1 + 0.25 * max(0, actionsToday - 1))
}
base: watch 0.02 / diary 0.04 / create 0.05 / share 0.02 / micro 0.005
```
`actionsToday` 已在 `LifeMemory` 里（rhythm.ts:14），跨天 `dayKey` 清零逻辑现成。
长回合（写 60 分钟）比短回合（翻 5 分钟收藏）疼得多——这是 §1.4「连做 4 轮只掉 0.07」的直接解药。

### 3.7 分档上线（每档都能单独回退）

## 5. 风险清单：什么时候「像人」会变成「像噪声」

- **R1 随机无后果 = 噪声。** 任何新引入的 `rng()` 必须落到持久状态并有下次的影响
  （范式是 `connectMisses` + `lastMissAt` 回落：随机一次 → 记忆 → 行为概率改变 → 随时间自愈）。
  反例红线：`abandoned` 只写链、不进 `driveAcc` → 三次之后她与没被中断前毫无区别。
- **R2 累积触发把「想做」变成「到点」。** acc 线性涨到 1.0 就是新节拍器。
  防：`ACC_RATE` 随情境与当日轮数非线性（当日第 N 轮后 acc 增速 ×0.6），并保留 ±15% 抖动；
  观测上盯 P2 的 std（节拍器的 std≈0）。
- **R3 盈余驱动 + 溢出与平台风控对撞。** share/create 都倾向「写出去」。
  防：v3 只让盈余驱动选**私下行**（讲给自己/写草稿不发），平台写仍由既有 `writeGapSec` traffic guard
  独立拦（rhythm.ts:39-40 的分层裁决）；S2/S3 阶段 micro action 一律不碰写接口。
- **R4 情境阈值的自我强化回路。** 她越在深夜动 → affinity 越偏深夜 → 白天阈值更高 → 更不动。
  防：限幅 ±0.10 + 每周重算 + 样本 <8 回合不更新；监控 P8。
- **R5 步骤队列把回合拖成背景常驻。** 每步一次 tick，回合可能占满几十分钟生命。
  防：`pendingRound` 超过 90 分钟未走完自动 `abandoned`；`nextCheckDelay` 3–7 分钟不变（别为队列改评估节拍）。
- **R6 边际成本演成隐性上限。** 成本太狠 → tired 门天天拦 → 等于把被否决的「每日 ≤3 次」从后门放回来。
  防：P5 同时设**上界**告警：tired 拒绝 >3 次/天即回退 §3.5 参数。
- **R7 观测期混淆因果。** 10-26→10-31 的样本里混着两次进程重启（10-31 02:07/03:13）与权限上线，
  且 10-15→10-27 十三天是机器关机不是她的静默。
  防：v3 上线时先给 3 天基线窗（不动代码），再开 7 天观测窗，窗口内 incident.md 必须记录每次重启，
  统计脚本对「重启后 30 分钟内」的回合单独打标。
- **R8 把夜行当缺陷修。** 本文 §2/§3 的所有机制都不得产生「夜里回合数下降」的净效果；
  若 P8 显示下降，按主人裁决判为设计缺陷而非她的「作息不健康」。
